01 — Color Science

Why OKLCH, not hex or HSL

The original Panda colors were chosen by eye — which is fine and they look great. But defining them in OKLCH means the math matches the perception.

👁

Perceptual Lightness

L in OKLCH maps to how bright your eye actually sees the color. Two colors with the same L feel equally bright — unlike HSL where yellow appears much lighter than blue at the same value.

🎯

Consistent Variants

Want Panda Midnight (darker) or Panda Bamboo (lighter)? Just adjust L uniformly across all tokens. Every variant is mathematically derived from the same source — no eyeballing.

♿

WCAG AA Built-in

Because L is perceptual, contrast ratios are predictable. You can guarantee 4.5:1 by setting L thresholds — not by testing each pair manually in a contrast checker.

🖥

P3 Wide Gamut

Modern Apple displays, Samsung AMOLED, and most 2024+ monitors support Display P3. OKLCH lets Panda use those extra 30% of colors where available. Hex can't express them at all.

📐

Human Readable

oklch(72% 0.22 355) — you can read this. L=72 (mid-bright), C=0.22 (vivid), H=355 (hot pink). Compare to #ff75b5 — which tells you nothing.

🔄

Single Source, Many Outputs

OKLCH is the source format. The generator compiles to hex, HSL, CSS vars, JSON tokens, and anything else a port needs. Change one value upstream, every port updates.

03 — Semantics

Color roles — what each token means

This is what makes it a system, not just a palette. Each color has a defined semantic role. Ports map these roles to their own token format.

pink — Keywords & Operators

Reserved words, operators, CSS properties, JSX tags. The most visually prominent token. const, return, import, =>

cyan — Functions & Methods

Function calls, method names, built-ins, class names. Second most common token. console.log(), useState, Array

green — Strings & Markup

String literals, template literals, HTML attribute values, CSS values, Markdown links. "hello", `${name}`

orange — Numbers & Constants

Numeric literals, boolean values, null/undefined, CSS units, enum values. 42, true, null, 16px

purple — Types & Interfaces

TypeScript types, interfaces, generics, CSS selectors, HTML tags. string, Interface, <div>

yellow — Variables & Properties

Variable declarations, object keys, CSS custom properties. const name, obj.key, --color

comment — Comments & Docs

Inline comments, block comments, JSDoc, docstrings. Should be subtle — readable but never distracting. // note, /** */

fg — Default Text

All uncolored text — punctuation, plain identifiers, prose. High contrast against bg. Must pass WCAG AA at minimum.

05 — Code

What the source code looks like

Three key files. Everything else is generated from these.

src/tokens.ts TypeScript
// THE single source of truth for all Panda colors. // All values defined in OKLCH. Hex is derived, not authored. export const pandaTokens = { // Syntax colors pink: { oklch: 'oklch(72% 0.22 355)', role: 'keyword' }, cyan: { oklch: 'oklch(75% 0.13 220)', role: 'function' }, green: { oklch: 'oklch(88% 0.18 175)', role: 'string' }, orange: { oklch: 'oklch(80% 0.15 65)', role: 'number' }, purple: { oklch: 'oklch(68% 0.16 295)', role: 'type' }, yellow: { oklch: 'oklch(91% 0.17 98)', role: 'variable' }, // UI colors bg: { oklch: 'oklch(15% 0.02 270)', role: 'background' }, surface: { oklch: 'oklch(19% 0.02 268)', role: 'surface' }, fg: { oklch: 'oklch(92% 0.02 272)', role: 'foreground' }, comment: { oklch: 'oklch(60% 0.04 275)', role: 'comment' }, } as const export type TokenName = keyof typeof pandaTokens
src/variants.ts TypeScript
// Variants are derived by adjusting L in OKLCH. // Same H and C = same hue identity. Only brightness changes. // This is the OKLCH superpower — HSL can't do this reliably. import { pandaTokens } from './tokens' import { adjustL } from './convert' export const variants = { /** Default dark theme */ dark: pandaTokens, /** Deeper, richer background — for Pro */ midnight: adjustL(pandaTokens, { bg: -4, surface: -3 }), /** Softer, misted dark — for Pro */ mist: adjustL(pandaTokens, { bg: +3, all: -5 }), /** Light theme — Panda Bamboo */ bamboo: adjustL(pandaTokens, { bg: 97, surface: 93, fg: 15, // Syntax colors darken significantly for light bg contrast pink: -18, cyan: -15, green: -25, }), /** High contrast — for accessibility / WCAG AAA */ storm: adjustL(pandaTokens, { all: +8, bg: -3 }), }
generators/vscode.ts TypeScript
// Generates the VS Code theme JSON from panda tokens. // Every other port has its own generator — same token input, different output shape. import { toHex } from '../src/convert' import { PandaTokens } from '../src/tokens' export function generateVSCode(tokens: PandaTokens) { const c = toHex(tokens) // convert all oklch → hex return { name: 'Panda Syntax', type: 'dark', colors: { 'editor.background': c.bg, 'editor.foreground': c.fg, 'editorLineNumber.foreground': c.comment, // ... all UI tokens }, tokenColors: [ { scope: ['keyword', 'storage'], settings: { foreground: c.pink } }, { scope: ['entity.name.function'], settings: { foreground: c.cyan } }, { scope: ['string', 'string.quoted'], settings: { foreground: c.green } }, { scope: ['constant.numeric'], settings: { foreground: c.orange } }, { scope: ['storage.type', 'entity.name.type'], settings: { foreground: c.purple } }, { scope: ['variable', 'meta.object-literal.key'], settings: { foreground: c.yellow } }, { scope: ['comment'], settings: { foreground: c.comment, fontStyle: 'italic' } }, ] } }

07 — Port DX

How a port maintainer uses this

Port repos become thin adapters. They import tokens, map to their format. They never define a color themselves.

panda-syntax-zed / theme.ts TypeScript — port example
// A port is now just a thin mapping layer. // No hex values. No color decisions. Just format translation. import { panda, toHex } from '@pandatheme/colors' const c = toHex(panda.dark) export const zedTheme = { name: "Panda Syntax", appearance: "dark", style: { background: c.bg, foreground: c.fg, "syntax.keyword": { color: c.pink, font_style: "normal" }, "syntax.function": { color: c.cyan }, "syntax.string": { color: c.green }, "syntax.number": { color: c.orange }, "syntax.type": { color: c.purple }, "syntax.variable": { color: c.yellow }, "syntax.comment": { color: c.comment, font_style: "italic" }, } } // Panda Pro? Just swap the variant: const cMidnight = toHex(panda.midnight) export const zedMidnight = { ...zedTheme, style: { ...zedTheme.style, background: cMidnight.bg } }

Why this architecture is the right call

Single source of truth. You change one OKLCH value in tokens.ts and every port — VS Code, Cursor, Zed, iTerm2, WezTerm, Figma — updates on the next release. No hunting through JSON files.

Variants for free. Panda Midnight, Bamboo (light), Storm (high contrast) are not separate design decisions — they're mathematical transformations of the same L axis. That's what OKLCH gives you that HSL cannot.

The npm package is the moat. Once ports import @pandatheme/colors, the entire ecosystem depends on this repo. It becomes the canonical reference — exactly what Dracula's spec page gestures at but doesn't technically deliver.
